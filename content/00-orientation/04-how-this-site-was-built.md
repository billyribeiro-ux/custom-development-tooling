# How This Site Was Built (Dogfooding)

Here's something a little unusual about this course: **it is built by the exact kind of tooling it teaches.** Every page you're reading — including this one — was generated by a script. That's not a gimmick; it's the single best teaching device we have. The word for it is *dogfooding*: using your own product.

## The whole site in one sentence

A folder of Markdown files plus a manifest, turned into linked HTML pages by one Node script, served as plain static files. That's it.

Let's make that concrete.

## The pieces

```text title=how-it-fits-together
course.json                 # the MANIFEST: every module + lesson, in order
content/**/*.md             # the SOURCE: one Markdown file per lesson
templates/page.html         # the SHELL: HTML with {{placeholders}}
tools/generate-pages.mjs    # the GENERATOR: turns source -> HTML
assets/styles.css, app.js   # styling + Monaco editor wiring
site/                       # the OUTPUT: generated HTML (never edited by hand)
```

The flow is a straight line:

```text title=the-pipeline
course.json + content/*.md  ->  generate-pages.mjs  ->  site/*.html
       (source of truth)          (the tool)            (the artifact)
```

## Why a generator instead of writing HTML by hand?

This course has 107 lessons. Imagine hand-writing 107 HTML files, each with the same header, the same progress bar, and **correct** Previous/Next links pointing at their neighbors. Now imagine you reorder two lessons. You'd have to fix the navigation on every affected page by hand, and you *will* make a mistake.

With a generator, the order lives in one place — `course.json` — and the script computes every Previous/Next link and progress number from it. Reorder a lesson, rebuild, done. **The navigation can never drift, because no human maintains it.**

> [!DOGFOOD]
> This is the first and most important lesson of tooling, demonstrated live: *move repetitive, error-prone work from humans to a script that does it perfectly every time.* The Previous/Next buttons at the bottom of this page were placed by the generator, not by me.

## The "source vs artifact" distinction

Notice that `site/` is in `.gitignore` — we never commit it. Why throw away the actual website?

Because `site/` is an **artifact**: it's *derived* from the source. If we committed it, it could drift out of sync with the Markdown, and every change would create a noisy, meaningless diff. Instead we commit the *source* (Markdown, manifest, generator) and rebuild the artifact whenever we need it — locally, or in CI before deploying. This source-vs-artifact idea is so fundamental we devote a whole lesson to it in Module 1.

## A peek at the generator

You'll dissect the real generator line by line in Module 5. For now, just see its shape — it's small and readable:

```javascript title=generate-pages.mjs (excerpt)
// Read the manifest (the single source of truth for order)
const course = JSON.parse(await readFile('course.json', 'utf8'));

// Flatten modules into one ordered list of lessons, then compute neighbors
const flat = buildLessonGraph(course);

// For each lesson: render its Markdown, fill the template, write the HTML
for (const lesson of flat) {
  const body = marked.parse(await readFile(lesson.contentPath, 'utf8'));
  const html = fill(pageTemplate, { body, /* prev, next, progress... */ });
  await writeFile(lesson.outName, html);
}
```

That's the heart of it: read, transform, write. Most tooling is some version of those three verbs.
